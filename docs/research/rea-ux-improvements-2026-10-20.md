# Great100 UI/UX 개선과 REA 검증

프로젝트를 연 사용자가 **지금 필요한 작업을 찾고, 해당 장면을 고친 뒤 출력까지 이어 가는 흐름**을 개선했다. 기존 크림·녹색 화면을 유지하면서 작업 순서, 안내 문구, 단계 이동, 작은 화면 조작을 정리했다. API 키나 추가 SQL은 필요하지 않다.

## 관찰과 적용

| 관찰한 문제 | 적용한 동작 |
| --- | --- |
| 전체 검토에서 여섯 준비·점검 패널이 장면 보드보다 앞에 있었다. | 제작 현황과 지금 할 일을 먼저 표시하고, 장면 보드 다음에 미리보기와 목적별 준비 도구를 배치했다. |
| 화면이 비어 있어도 사용자가 직접 누락 장면을 찾아야 했다. | 선택된 화면 수·녹음 연결 수·썸네일 상태를 표시하고 첫 미선택 장면이나 썸네일로 바로 이동한다. 실제 파일 유효성 검사는 자료 점검에서 수행한다고 구분한다. |
| 미래 단계 메뉴는 활성화돼 보이지만 클릭해도 이동하지 않았다. | 열린 프로젝트의 편집 단계는 바로 이동하며, 완료 단계는 기존 출력 검사 통과 후 활성화한다. 현재 단계에 `aria-current`를 제공한다. |
| 페이지 위치로 계산한 진행률은 실제 제작 완료율처럼 보였다. | 현재 단계 이름과 제작 단계 위치를 표시한다. 화면 선택 현황은 전체 검토에서 별도로 제공한다. |
| API 미연결 환경에서 ‘후보 생성’과 ‘Mock mode’의 의미가 불명확했다. | 이미지 업로드를 기본 동작으로 강조하고, 예시 만들기는 레이아웃 확인용이라고 표시한다. 녹음과 음악은 선택 사항이라고 안내한다. |
| 장면 편집에서는 음악·구조 편집과 자막 설정을 지난 뒤에 이미지 후보를 고를 수 있었다. | 장면 이동과 현재 정보를 먼저 보여주고, 이미지 준비 바로 다음에 후보를 배치한다. 장면 나누기·합치기와 전체 음악 설정은 편집 작업 아래에 둔다. |
| 최소 너비 1080px과 작은 버튼이 휴대폰 조작을 어렵게 했다. | 320px부터 대응하며, 단계 메뉴 가로 이동·현재 단계 노출·한 열 폼·44px 조작 영역·키보드 포커스·동작 줄이기 설정을 지원한다. |

이미지·녹음 준비 바로가기는 이동하면서 해당 패널을 펼치고 포커스를 옮긴다. 자료 점검 바로가기는 점검 위치로 이동하며 검사를 자동 실행하지 않는다. 이동만으로 저장하거나 파일을 업로드하지 않는다. 기존 후보 비교·일괄 배치·재시도·실행 취소 상태는 같은 컴포넌트에서 유지한다.

## REA로 확인한 범위

Vrew 공개 체험판의 보관된 JavaScript 분석을 재사용했다. 부분 그래프에서 `undoAction` 문자열을 조회했지만 대응하는 시작 노드를 찾지 못했다. 이는 구현이나 기능이 없다는 증거가 아니며, 이번 변경을 Vrew 내부 명령 처리의 복원 결과라고 설명하지 않는다.

REA의 실제 브라우저 관찰에서는 **Vrew 4.7.2**의 새 프로젝트·프로젝트 열기 진입점과 File/Home/Edit/Captions/Format/Insert/AI Voice 등의 목적별 메뉴, Undo/Redo·Split/Merge의 편집기 외곽을 확인했다. 공개 체험 프로젝트는 브라우저 호환 안내와 로딩 상태가 남아 실제 자막 편집·저장 동작까지 검증하지 못했다. REA 시나리오 도구의 공개 사이트 탐색도 실행 오류가 있어, 별도로 소유한 임시 Playwright 브라우저에서 데모를 요청한 뒤 REA로 결과 화면을 관찰했다. 로그인된 계정이나 비공개 프로젝트는 사용하지 않았다.

목적별 도구 구성을 참고하되, **지금 할 일 요약·단계 자유 이동·업로드 우선·작은 화면 대응은 Great100의 자체 설계 선택**이다. Vrew의 스타일·코드·자산을 복사하지 않았다.

Great100에는 REA `capture_browser_scenario`로 다음 일곱 동작을 실행했다. 모두 완료됐으며 최종 접근성 트리와 화면을 확보했다.

1. 프로젝트 재개 버튼 확인
2. 프로젝트 열기
3. 전체 검토 단계로 직접 이동
4. 이미지 준비 도구 이동·펼치기
5. 녹음 대본 도구 이동·펼치기
6. 첫 미선택 장면 열기
7. 작업 보드 복귀

REA의 개선 전·후 DOM/접근성 비교는 `changed`로 보고됐다. 이 결과 자체가 사용성 향상 수치나 작업 시간 감소를 증명하지는 않는다. 네트워크는 연결 이후 관찰만 포함하며, 스크립트 본문·저장소 등 요청하지 않은 영역은 제외됐다. Evidence ID·커버리지·임시 전체 내보내기 경로는 [검증 기록](rea-ux-evidence-2026-10-20.json)에 보관했다. 전체 번들은 약 50MB로 임시 경로에만 내보냈으며 장기 보관은 보장하지 않는다.

## 구현 검증

- 전체 회귀 테스트 **69개 파일·478개 통과**, TypeScript 및 배포 빌드 통과.
- 실제 Chromium에서 **320·390·768·1024·1440px × 여섯 제작 화면 = 30개 배치**를 검사했다. 가로 넘침 없이 현재 단계와 하단 이동 버튼을 확인했다.
- 실제 미선택 장면 두 개를 열어 후보 선택·작업 보드 복귀·현황 갱신·출력 단계 진입을 확인했다. 준비 도구 바로가기만 사용했을 때 프로젝트 저장 시각은 바뀌지 않았다.
- 새 문구로 바꾼 자막의 미리보기·실행 취소·재열기·대본 복사·TXT·실제 MP4 제작을 회귀 검증했다. 출력은 **31초·465프레임**, 음성·영상 디코딩과 ZIP의 MP4 포함을 확인했다.
- 이미지·동영상·녹음·음악 **54개 원본의 SHA-256**과 원본 제작안이 유지됐다. 검증 중 `/api/` 요청과 페이지 오류는 각각 0개였다.

검증은 합성 자료와 개발용 브라우저 저장소를 사용했다. 로그인된 운영 Supabase/R2 쓰기, 실제 사용자 제작 시간, 패키징된 Tauri 실행은 이번 검증에 포함하지 않았다.
