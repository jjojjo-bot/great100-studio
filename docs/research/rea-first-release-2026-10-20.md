# Great100 Studio의 REA 첫 적용 결과

2026년 10월 20일. [적용 계획](rea-adoption-plan-2026-10-20.md)의 A 기준 이미지 처리와 B 편집 이력을 구현했다. 다음 작업은 C 편집 검증·형식 호환과 D 공통 시간 계산이다.

업로드한 인물 기준 이미지가 장면·썸네일 생성 요청에 함께 들어간다. 로컬 웹과 데스크톱은 프로젝트가 보관하는 원본 data URL을 읽고, 계정 자료는 저장 키로 새 접근 URL을 발급받아 원본을 읽는다. PNG·JPEG·WebP를 실제 내용으로 확인하고, 큰 이미지는 긴 변 1536px·3MB 이하의 참조 사본으로 준비한다. 원본은 프로젝트에 그대로 보관한다.

상단에는 실행 취소·다시 실행을 추가했다. 자막 문구·시간, 이미지 프롬프트·후보 선택, 이미지 효과, 음악 볼륨, 화면 전환·트림 설정을 최근 50개 편집 묶음으로 보관한다. 자막 드래그와 같은 입력란의 연속 입력은 한 묶음이다. 생성·업로드 완료와 계정 저장 버전은 이력에 넣지 않고 최신 프로젝트에 필요한 필드만 역변경한다. 원본이 실제 삭제된 선택 이력은 제거하며, 다른 프로젝트를 열거나 서버 최신 작업으로 교체하면 이력을 초기화한다.

Vrew에서는 기존 REA Evidence의 모듈 export를 조회해 실행 취소와 다시 실행의 진입점을 좁혔다. 메인 모듈의 실행 취소 연결은 장면 모듈의 `h3`, 다시 실행 연결은 `S0`로 이어진다. 해당 소스에는 실행 취소 명령, 다시 실행 목록과 재생 여부·편집 종류에 따른 조건이 있다. 추가 추적에서 재생 여부를 읽는 함수가 확인되어, 이 조건을 입력란 포커스 정책으로 해석하지 않았다. 입력란에서 브라우저의 기본 실행 취소를 유지하는 규칙과 필드 단위 이력은 Great100의 별도 설계다. [정적 분석 검증 기록](rea-vrew-editor-evidence-2026-10-20.json).

REA의 Vrew 런타임 시도는 Chromium 실행 후 첫 페이지 이동에서 실패했고, 소유한 브라우저 프로세스는 정리됐다. Vrew의 실제 편집 동작을 검증한 것으로 취급하지 않는다. Great100의 적용 결과는 자체 테스트와 실제 Chromium 조작으로 확인했다.

| 검증 | 결과 |
| --- | --- |
| Vitest 전체 | 33개 파일, 159개 테스트 통과 |
| TypeScript·운영 빌드 | `npm run build`의 타입 검사와 Vite 빌드 통과 |
| 큰 이미지의 실제 처리 | 7,432,464바이트 원본을 1,151,701바이트 JPEG 참조 사본으로 준비 |
| 장면·썸네일 참조 | 모의 생성 요청 5개 모두에 선택한 업로드 참조 포함 |
| 실제 자막 드래그 | 0~3초 자막을 1~4초로 이동 후 실행 취소 한 번으로 복구 |
| 생성 중 편집 | 자막 편집을 되돌려도 늦게 도착한 생성 후보 2개 유지 |
| 프로젝트별 이력 | 다른 프로젝트의 생성 완료가 현재 프로젝트의 이력을 바꾸지 않는 회귀 테스트 통과 |
| 실제 저장 | IndexedDB의 최종 자막·후보와 큰 기준 이미지 원본 보존 확인 |
| 이미지 디코더 호환 | `createImageBitmap`이 없는 경우 HTML 이미지 경로를 실제 브라우저에서 확인 |
| 브라우저 오류 | 검증 시 페이지 오류 0개 |

시간축 드래그 검증 중 고정 하단 바가 테스트 좌표를 가리는 경우를 확인했다. 자막을 화면 중앙으로 스크롤해 포인터가 실제 자막 막대에 도달하는 상태에서 드래그·복구 결과를 확인했다.

실제 과금되는 이미지 생성은 호출하지 않았다. 클라우드의 원본 읽기·저장 충돌·계정 전환과 Tauri의 호출 경로는 모의 테스트 범위이며, 운영 R2 계정과 패키징한 데스크톱 앱의 실동작은 별도 검증 대상이다. Vite는 큰 청크에 대한 경고를 출력했으며 빌드는 성공했다.
